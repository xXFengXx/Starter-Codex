# 目标

让项目内所有 Markdown 文档以中文呈现，同时保持命令、路径、标识符、结构和自动化行为不变。

# 范围

- 翻译仓库内全部 `.md` 文件的自然语言内容。
- 将 Markdown 模板和 PR Package 生成器改为默认输出中文。
- 让需求校验器支持中文契约标题。
- 保留代码块、命令、路径、标识符、frontmatter 键和验收编号。

# 非目标

- 翻译 TypeScript、JavaScript、JSON 或工作流文件中的代码标识符。
- 改变产品功能或 Harness 生命周期语义。
- 翻译第三方依赖中的 Markdown。

# 约束

- `node_modules/`、`dist/` 和 Git 元数据不属于翻译范围。
- 翻译后所有 Harness 门禁必须继续通过。
- Agent 指令必须保持明确、可执行且只有一个事实来源。
- 历史证据中的命令和状态值保持原文，确保可复现。

# 验收标准

- **AC-001**: 仓库内所有受控 `.md` 文件的标题、说明和叙述性内容均为中文。
- **AC-002**: 命令、路径、标识符、frontmatter 键、状态值和验收编号保持可执行与可追踪。
- **AC-003**: `AGENTS.md` 与 `CLAUDE.md` 中文化后仍指向同一套规范，没有复制第二套流程。
- **AC-004**: Harness 模板与 PR 生成器以后默认生成中文 Markdown。
- **AC-005**: 需求校验器同时正确校验中文契约结构。
- **AC-006**: `npm run check`、`npm test` 和 `npm run build` 全部通过。

# 风险

- 翻译结构标题可能破坏校验器；通过双语标题映射和测试控制风险。
- 翻译命令或标识符可能破坏自动化；这些内容明确保留原样。
- 历史证据被改写可能失真；只翻译叙述，不改变结果和数值。

# 验证预期

- 枚举全部受控 Markdown，检查是否残留非必要英文叙述。
- 运行需求校验与 Harness 单元测试。
- 运行完整 TypeScript、测试和构建门禁。
- 生成中文 PR Package 并人工检查结构。
