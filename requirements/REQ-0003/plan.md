# 实施计划

## 方案

将文件选择职责放在主进程，通过共享 IPC 通道向渲染进程返回所选路径；将扩展名、大小和可读性校验集中在 `DocumentService`，确保界面过滤无法成为唯一防线。导入写入采用失败清理，界面负责触发选择、显示结果或错误并刷新列表。自动化测试使用 Node 内置测试运行器与 `.harness/runtime/REQ-0003/` 隔离目录。

## 步骤

- [x] 在共享类型、主进程和 preload 中增加文件选择 IPC，并配置仅 `.txt`、`.md` 的原生选择器。
- [x] 在 `DocumentService` 中加入大小写不敏感的扩展名校验、10 MiB 边界校验和读取前校验。
- [x] 使导入持久化具备失败清理能力，避免部分文件、内容或元数据残留。
- [x] 接通渲染进程导入按钮，处理取消、成功刷新和用户可见错误。
- [x] 将 preload 打包为 sandbox 可加载的单文件，并用隐藏 Electron 窗口验证桥接真实可用。
- [x] 增加隔离自动化测试，覆盖允许格式、大小边界、拒绝路径、取消与 IPC 绕过。
- [x] 运行完整 Harness 门禁并生成 PR Package。
