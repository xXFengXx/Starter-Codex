# 目标

修复当前不可用的文档导入功能，使用户能够从应用界面选择并导入文本或 Markdown 文档，同时通过前后端一致的文件类型与大小校验，阻止不受支持或过大的文件进入知识库。

# 范围

- 用户点击现有“Import”入口后，系统打开原生文件选择器。
- 文件选择器允许用户选择扩展名为 `.txt` 或 `.md` 的单个文件，扩展名匹配不区分大小写。
- 导入服务在可信主进程边界再次校验文件扩展名与文件大小，不能只依赖文件选择器过滤。
- 单个文件大小上限为 `10 MiB`（`10 * 1024 * 1024 = 10,485,760` 字节），恰好等于上限的文件允许导入。
- 合法文件沿用现有导入流程保存源文件、文本内容和文档元数据；成功后刷新文档列表，并让用户能够看到新导入的文档。
- 用户取消选择时不执行导入，也不显示错误。
- 文件不存在、类型不受支持、大小超过限制或读取失败时，向用户显示清晰、可操作的错误信息，且不得留下源文件副本、内容文件或元数据等部分导入结果。

# 非目标

- 不支持 `.markdown`、富文本、PDF、Word、图片或其他文件格式。
- 不在本需求中实现多文件或文件夹批量导入、拖放导入、远程 URL 导入。
- 不改变导入后的索引、检索、问答或删除逻辑。
- 不提供超过上限文件的压缩、拆分或自动转换能力。
- 不依据文件内容推断格式；本需求以文件扩展名作为允许类型的判定依据。

# 约束

- 文件大小采用二进制兆字节口径；界面文案可显示为“10 MB”，实际校验阈值必须是 `10,485,760` 字节。
- 校验必须在读取完整文件及写入持久化数据之前完成，避免过大文件造成不必要的内存或磁盘占用。
- 主进程或 Service 层必须执行最终校验，渲染进程传入的任意路径均视为不可信输入。
- IPC 通道统一定义在 `src/shared/types.ts`，不得由各层分别硬编码。
- `DocumentService` 继续通过构造函数注入 `PersistenceService`。
- TypeScript 保持严格模式并仅使用命名导出。
- 自动化测试只能读写 `.harness/runtime/`，不得接触真实 Electron `userData`。

# 验收标准

- **AC-001**: 点击“Import”后出现原生文件选择器，其可选文件过滤为 `.txt` 和 `.md`；取消选择后界面与持久化数据均保持不变。
- **AC-002**: 用户选择存在、可读且不大于 `10,485,760` 字节的 `.txt` 文件后，文件成功导入，文档列表刷新并显示对应文档。
- **AC-003**: 用户选择存在、可读且不大于 `10,485,760` 字节的 `.md` 文件后，文件成功导入，文档列表刷新并显示对应文档。
- **AC-004**: `.txt` 与 `.md` 扩展名匹配不区分大小写；其他扩展名即使绕过文件选择器直接调用 IPC，也会被拒绝并得到明确的“不支持文件类型”错误。
- **AC-005**: 大小恰好为 `10,485,760` 字节的允许类型文件可导入；大小为 `10,485,761` 字节或更大的文件会在读取完整内容和持久化写入前被拒绝，并得到明确的“文件超过 10 MB”错误。
- **AC-006**: 文件不存在、不可读或导入过程失败时，用户可见错误能够说明失败原因；文档列表不会新增记录，持久化目录中不会留下该次操作的部分导入数据。
- **AC-007**: 自动化测试覆盖两种允许格式、大小边界、大小超限、类型拒绝、取消选择和直接 IPC 绕过界面过滤的场景。
- **AC-008**: `npm run check`、`npm test`、`npm run build` 以及 `npm run harness:verify -- REQ-0003` 全部通过。

# 风险

- 渲染进程可绕过界面过滤直接调用 IPC；通过在主进程或 Service 层执行最终校验缓解。
- 导入中途失败可能留下文件与元数据不一致；实施时应在提交元数据前完成校验，并对已产生的中间文件执行可验证的清理或原子化写入。
- “10 MB”存在十进制与二进制歧义；本契约明确采用 `10 MiB` 的字节阈值并要求边界测试。
- 原生文件选择器与 Service 测试边界不同；通过将选择器交互、IPC 防护和 Service 行为分别验证缓解。

- 在 `.harness/runtime/` 中使用临时测试文件，不读取或修改用户真实数据。
- 运行 Requirement Contract 与追踪校验、TypeScript 检查、完整测试、构建、范围及敏感信息审查。
